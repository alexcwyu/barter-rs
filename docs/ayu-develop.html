Purpose and scope

Typed Rust trading system joining market/account events, strategy-generated order requests, risk approval, execution channels and session analytics.

Design decisions

Decision Rationale Tradeoff Evidence
Split synchronous policy from asynchronous channels. Processor handles events and decisions while runtime forwards I/O into the central feed. Channel and audit configuration determine run behavior; asynchronous I/O is not distributed execution. process (L144) / init_internal (L340)
Make strategy, risk and execution generic interfaces. Different policies/clients can share the typed engine. Users must implement real risk rules: the default is an approve-all demonstration. Engine (L106) / DefaultRiskManager (L100)

Strengths and limits

Strengths

  • Order generation explicitly records both refused requests and approved in-flight requests. generate_algo_orders (L46)

Limitations

  • Default risk manager performs no risk checks; stop order claims in older cross-system descriptions conflict with Market/Limit OrderKind. DefaultRiskManager (L100) / OrderKind (L158)
  • Instrument variants do not by themselves substantiate FX/equity venue support, production safety or distributed deployment. InstrumentKind (L22) / ExecutionClient (L24)
  • Inspected MockExchange supports Market only; native Limit/TIF request types do not establish Limit/TIF simulated execution. validate_order_kind_supported (L396) / OrderKind (L158)
